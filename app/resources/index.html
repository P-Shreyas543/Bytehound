1. Introduction & Getting Started

What is the Serial Monitor App?

The Serial Monitor App is a powerful, hardware-agnostic telemetry and control dashboard. It reads raw byte streams over a serial connection (UART/USB), parses them using a custom dictionary that you define, and displays the data in live tables and high-speed graphs.

Connecting Your Hardware

To get your hardware (NXP, STM32, Arduino, etc.) talking to the app:

  1. Connect your hardware to your computer using a USB cable or Serial adapter.
  2. Ensure your firmware is programmed to output bytes in the standard packet format: [Header] + [ID] + [Length] + [Data] + [CRC]. (See Section 5 for protocol details).
  3. Open the Serial Monitor App.
  4. In the Connection panel (top-left):
    • Select your hardware's actual COM port (e.g. COM7). Click "Refresh" if it isn't listed.
    • Set the Baud Rate to match your hardware (e.g., 115200).
  5. Click Connect.

Active Polling

If your hardware only sends data when "asked", check the Start Polling box in the Settings panel. This activates the background engine to continuously send data requests to your hardware based on your defined schedule.

2. Core UI Panels & Features

The application is heavily modular. You can drag, drop, stack, and resize any of the panels to build your perfect workspace.

The Main Data Table

Located in the center of the screen, this table displays all your decoded numeric variables (like Voltage, Current, or Temperature) in real-time. It automatically scales the raw bytes into human-readable engineering units.

Live Plot

To graph variables in real-time:

  1. Check the small box next to a variable's name in the Main Data Table.
  2. The Live Plot panel will instantly start graphing that data. You can check multiple boxes to overlay different metrics.

Bitfields Panel

If your hardware packs multiple Boolean (True/False) flags into a single byte (like Fault states, Relay statuses, or Switch inputs), the Bitfields panel breaks them out into individual, readable ON/OFF indicators.

Enums Panel

Sometimes hardware sends state integers (e.g. 0 = OFF, 1 = PRECHARGE, 2 = RUN). The Enums panel translates these raw numbers into clear, readable text labels so you don't have to memorize state codes.

Raw Console

Found at the bottom of the screen, the Raw Console shows the exact Hexadecimal bytes flowing into and out of the application in real-time. Use this to debug communication errors or verify packet structures.

Activity Log

The Activity Log tracks major application events, such as when configurations are loaded, when connections are established, or when logging starts and stops.

3. Controlling Your Hardware

The app isn't just for looking at data; you can actively command your hardware.

TX Commands

The TX Commands panel provides custom push-buttons (defined in your Excel configuration) that instantly send predefined hex payloads to your hardware. This is perfect for triggering Resets, clearing faults, or toggling modes.

Parameter Editing

The Parameter Editor allows you to change internal variables on your hardware live. Just type a new number into the editable field and hit Enter. The app will automatically convert your number into scaled bytes, calculate the checksum, and transmit it to your hardware's memory address.

4. Logging and Data Analysis

Recording Logs

To save your telemetry for later review:

  1. Click File → Start Logging in the top menu.
  2. Choose where to save your file. The app will begin recording all incoming traffic to _raw.csv and _decoded.csv files on your hard drive.
  3. When finished, click File → Stop Logging.

Replaying a Test

If you want to watch a recorded test again exactly as it happened:

  1. Disconnect your live hardware.
  2. Click File → Load Log... and select your _raw.csv file.
  3. The app will instantly replay the test stream through your live tables and plots.

The Analysis Suite

For deep-diving into external test data (like Dyno logs):

  1. Go to Tools → Analysis Suite.
  2. Click Load Logs and select your Excel .xlsx test files.
  3. You can place cursors to measure time deltas, compare multiple log files simultaneously, and use the Scatter → X-Y Plotter to graph parameters against each other.

5. Customizing Your Data (The Excel Config)

The Serial Monitor App uses an Excel dictionary to know how to decode your hardware's raw bytes. You don't need to write any Python code!

To get started, click File → Export Template, save the .xlsx file, and open it in Excel. The workbook contains several tabs (sheets) that control everything in the app. Once you edit the template, save the Excel file and click File → Import Config in the app to apply your changes instantly!
  • variables: Defines your standard numeric data. Tells the app what the variable is called, what frame_id to look for, and how to scale the raw number into a real-world value.
  • bitfields: Defines how individual bits within a single byte are broken out and named in the Bitfields panel.
  • enums: Maps raw integers to readable text statuses (e.g., 0=Off, 1=Running) for the Enums panel.
  • tx_commands: Defines the custom push-buttons that appear in the TX Commands panel.
  • tx_command_fields: Defines the editable numeric inputs that appear in the Parameter Editor panel.
  • polling_schedule: If your hardware uses a Request/Response architecture, this sheet tells the app exactly what IDs to request and how often (in milliseconds) to ask for them.
  • protocol: Contains advanced communication settings, such as Byte Order (Endianness) and Checksum algorithm. Leave this alone unless you are the lead firmware engineer!
